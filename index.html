smog_map/

Nov 2026 · solo · full-stack

Smog Map

FastAPISQLAlchemy 2SQLitehttpxNext.js 15TypeScriptLeafletRechartspytest

Air quality map for Poland on the public GIOŚ API. An asyncio background task in the FastAPI lifespan syncs ~800 sensors hourly through an httpx client with a semaphore (3 concurrent) and retries, upserts readings into SQLite with ON CONFLICT DO UPDATE in 500-row batches and keeps a 30-day window. Station index uses GIOŚ thresholds (worst pollutant wins); nearest stations via haversine. 10 REST endpoints; SMTP alerts with a 6-hour cooldown and unsubscribe tokens. Next.js 15 App Router with ISR (revalidate 600 s), Leaflet loaded client-only via dynamic(). Frontend types generated from the OpenAPI schema with openapi-typescript, so a changed Python response model breaks the TS build. 16 pytest tests.

A map of Poland that shows how clean the air is right now. Every hour it collects fresh numbers from the official government stations, shows which cities are the worst and the cleanest, draws a chart for the last week and lets you compare two cities. You can also leave your e-mail and get a message when the air near you gets bad.

  • ~800sensors
  • 1hsync
  • 30days history
  • 16tests

cog_chain/

Mar – Jun 2026 · solo · Windows & Android

Cog Chain

Godot 4.6C# / .NETJolt PhysicsFirebase RESTDocFXBlender

~3k lines of C# on Godot 4.6. Gear meshing is a BFS over a graph rooted at the motor: each node checks centre distance against summed radii and axis alignment (dot product of basis vectors), plus type compatibility from GearType resources; rotation direction alternates per depth. Levels, gear configs and star limits are data-driven .tres resources. Global singletons (Game/UI/Sound managers) run as autoloads. Accounts, cloud saves and the leaderboard talk to Firebase Auth and Realtime Database over async REST (HttpClient + System.Text.Json), with a local JSON save as fallback. EN/PL via Godot's CSV translations; docs in DocFX + UML.

A puzzle game about gears. You connect them to a motor so that a door opens or a lamp turns on. I did everything myself: the idea, the drawings, the 3D models, the video, the testing and the release. I also wrote a guide so new players know where to start.

3d_model_gallery/

Oct 2025 – Jan 2026 · solo · full-stack

3D Model Gallery

Three.jsNode.jsExpressPostgreSQLDockerNginx

Express 5 (ES modules) REST API: POST /api/upload with Multer, GET and DELETE /api/models, metadata in PostgreSQL through a pg connection pool. Vite frontend with a Three.js viewer (GLTFLoader, OrbitControls) that reads mesh, material, vertex and triangle counts and swaps materials for base colour, normal, AO, roughness, metalness, UV-checker and wireframe passes. Docker Compose runs db, app and Nginx on an isolated internal network with a named volume for Postgres; only Nginx is exposed. The proxy container runs SSH with key-only auth, Fail2ban (3 tries → ban) and an iptables policy of default DROP with SSH allowed from one host. Health-check scripts per service.

A website where you upload a 3D model and look at it from every side, right in the browser. You can switch views to check each texture separately, like a 3D artist does before handing a model over. Anyone can start it with one command, and the server is protected from break-in attempts.

Sorting & Scheduler Benchmark

PythonBenchmarkingData viz

Python benchmark harness joining two courses, algorithm analysis and operating systems. It times sorting algorithms (e.g. insertion O(n²) vs merge O(n log n)) and SJF CPU scheduling on growing input sizes and plots measured time against the theoretical complexity curve on log-log axes.

A program that checks which way of sorting data is fastest, and how a computer should decide which task to do first. It runs real tests and turns the numbers into charts that anyone can read without a maths background.
